# GTFS Realtime-shaped model across the MVC interfaces

The data passed from `DepartureProvider` through the controller to `BoardView` uses GTFS / GTFS Realtime names and semantics (`route_short_name`, `trip_headsign`, `platform_code`, `StopTimeEvent{time, delay}`, `ScheduleRelationship`, `FeedHeader.timestamp`), even though the only source is the MVV website and not a GTFS feed. This gives the model a well-known, documented vocabulary and lets a future GTFS-based provider plug in without reshaping the view. The model is a flat subset rather than a faithful `FeedMessage → FeedEntity → TripUpdate` tree: GTFS-RT alone cannot be rendered (names and scheduled times live in static GTFS), and the extra nesting would carry IDs nothing on the device reads. Only enum values the source can produce are included (`Scheduled`, `NoData`); add `Skipped` or `route_type` when a source supplies them.

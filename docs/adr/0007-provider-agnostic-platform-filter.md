# Platforms are filtered on the Device, independent of the provider

The Device drops Departures whose `platformCode` isn't in the Board Selection's Platforms after any `DepartureProvider` fetch, as part of board selection. So every provider gets Platform filtering, whether or not its source can filter by Platform itself. Route Directions stay a provider concern, because the MVV request is built from them and `Departure` carries no Route Direction. In the Companion App, each provider implements one `TransitProvider` interface (`searchStations`, `routeDirections`, `platforms`). A provider that cannot list Platforms returns none, and the app then hides the Platform picker. Platforms match by exact text, as the provider names them (e.g. `2`, `U-Bahn Gleis 1`, `Pos. 3`). The app never lets the user pick a provider. It uses the `TransitProvider` named by the Device's `info` characteristic. `scripts/select_modules.py` injects that name from the compile-time `PROVIDER` (ADR 0003), so the app always matches the firmware actually flashed. For a provider name the app doesn't know, the app only allows editing WiFi.
